Section 01

៥ Status ស្នូលជាសកលក្នុង Database

រក្សាទុក Code តែ ៥ ម៉ាត់ក្នុង Database ប៉ុន្តែ Frontend បង្ហាញពាក្យ និងពណ៌ Badge ឆ្លាតវៃតាមប្រភេទ Venue

🟡 pending

រង់ចាំចាប់ផ្តើម

• Restaurant: ភ្ញៀវទើប Scan QR
• Cafe: រង់ចាំ Barista ទទួល
• Mart: រង់ចាំរៀបចំ Delivery

KDS: Pending Queue
🔵 preparing

កំពុងចម្អិន/រៀបចំ

• Restaurant: ចុងភៅកំពុងចម្អិន
• Cafe: Barista កំពុងឆុង
• Mart: បុគ្គលិកកំពុងរើសទំនិញ

KDS: In-Kitchen Cooking
🟣 ready

រួចរាល់

• Restaurant: រង់ចាំអ្នករត់តុលើក
• Cafe: ហៅលេខ Buzzer យក
• Mart: ច្រកថង់រួចរង់ចាំយក

KDS: Order Ready Alert
🟢 completed

បានបញ្ចប់

• Restaurant: ញ៉ាំ & បង់លុយបិទតុ
• Cafe: ភ្ញៀវបានទទួលកាហ្វេ
• Mart: ស្កេន គិតលុយ យកភ្លាម

POS: Closed & Archived
🔴 cancelled

បានបោះបង់

• ភ្ញៀវសុំប្តូរចិត្ត Cancel
• ទំនិញដាច់ស្តុក ឬខូច
• បោះបង់មុនពេលចម្អិន

Audit: Reason Logged

ដំណើរការប្រតិបត្តិការជាក់ស្តែងរវាង Cashier, KDS ផ្ទះបាយ និងអតិថិជន

Section 03

ស្ថាបត្យកម្ម Return (បង្វិលសង) & Exchange (ប្តូរទំនិញ)

ការគ្រប់គ្រងចរន្តទំនិញក្នុងស្តុក និងការកាត់កងចរន្តសាច់ប្រាក់ត្រឹមត្រូវ ១០០%

💸 Return / Refund

បង្វិលទំនិញយកប្រាក់វិញ

1. ស្កេនវិក្កយបត្រ: ទាញយកប្រវត្តិ Order ដើម និងជ្រើសរើសចំនួនទំនិញដែលត្រូវ Return។
2. ពិនិត្យគុណភាពស្តុក:
• ទំនិញនៅល្អ: បូកចូលស្តុកវិញ (+Stock)
• ទំនិញខូច/ផុតកំណត់: កត់ត្រាចូល Waste Log
3. សងប្រាក់: Update payment_status: 'refunded' និងចេញប័ណ្ណ Refund Receipt។
Database: orders.payment_status = 'refunded'
🔄 Exchange

ប្តូរយកមុខទំនិញថ្មី

A. ស្មើតម្លៃ ($10 = $10):

បូកទំនិញចាស់ចូល (+1) & កាត់ទំនិញថ្មីចេញ (-1) ➔ ភ្ញៀវមិនបាច់បង់បន្ថែម ($0.00)

B. លើសតម្លៃ (ទំនិញថ្មី $15 > $10):

ប្រព័ន្ធកាត់កង $10 ចេញ ➔ ភ្ញៀវបង់ប្រាក់បន្ថែមតែ +$5.00 ប៉ុណ្ណោះ

C. ខ្វះតម្លៃ (ទំនិញថ្មី $7 < $10):

ប្រព័ន្ធកាត់កងរួច ➔ Cashier សងលុយអាប់ត្រឡប់ជូនភ្ញៀវវិញ -$3.00

Inventory: Swap Stock & Settle Difference
